# Portable execution on cloud servers

The project has **no server-specific filesystem paths** and requires no site-specific
job scheduler, shared filesystem, CUDA device, or host-specific environment variables.
It runs with Python 3.10–3.12 on standard Linux CPU VMs; a container option is below.
We tested the same source on a CPU Linux environment, including launching scripts
from a different working directory. We have **not** tested every cloud vendor,
operating system, GPU runtime, or container runtime.

## Option A: Any ordinary Linux server with Python

```bash
# On the server, unpack the project wherever you have write access.
cd /path/to/AGT_PSRO_cloud_portable
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python experiments/quick/run_svi.py --scenario six_node_three_risk
python experiments/quick/run_psro.py --scenario six_node_three_risk --init all \
  --seeds 11 12 13 --steps 1000 --iterations 1 --threads 1 --skip-svi
python -m pytest tests/test_game_and_svi.py tests/test_results_safety.py -q
```

Use `python` instead of `python3` if that is the available interpreter. Run the
same commands on a login node or as a batch job on a cluster, according to the
provider's scheduling rules. Prefer Python 3.11 or 3.12 for broad PyTorch wheel
availability. All paths are resolved relative to the extracted source, **not**
the invoking working directory or your home folder.

For optional W&B logging, install `requirements-wandb.txt` and add `--wandb`.
See [WANDB_SETUP.md](WANDB_SETUP.md) for tested Bash launchers, online/offline tracking,
custom W&B hosts, syncing, and optional Docker W&B installation.
Authentication remains in your own environment (e.g., `WANDB_API_KEY`); **do not**
put secrets in the source or upload results containing private credentials.
W&B run files are directed to `results/wandb/` when enabled.

## Option B: Same CPU environment using Docker (if Docker is available)

```bash
docker build -t agt-psro:cpu .
# Persist generated results on the host:
docker run --rm -v "$(pwd)/results:/app/results" agt-psro:cpu \
    python experiments/quick/run_svi.py --scenario six_node_three_risk
docker run --rm -v "$(pwd)/results:/app/results" agt-psro:cpu \
    python experiments/quick/run_psro.py --scenario six_node_three_risk \
    --init scratch --seed 11 --steps 1000 --iterations 1 --skip-svi
```

The Dockerfile supplies a **CPU-only** PyTorch installation. Docker images must
be built where network package repositories are accessible; this image was
reviewed but not built here (no Docker daemon). GPU-accelerated execution needs
an appropriate PyTorch/CUDA install and matching host drivers/container runtime.
The code's current PPO training uses CPU tensors, so a GPU host does not by
itself make these experiments faster.

## Output policy

Everything generated by the **experiment commands** (SVI results, PSRO JSON,
metrics, plots) is saved under the source project's `results/` folder, including
when the launcher is invoked from another directory. `--output-root` may designate
only `results/` or a descendant, not the repository root or a foreign directory.
The atomic JSON writer rejects paths outside `results/`. A distinct configuration
fingerprint is used for each run; use separate seeds/condition pairs for concurrent
jobs. Python bytecode and package caches are not experimental data.

| Path | Contents |
|---|---|
| `results/data/svi/` | Exact SVI JSON |
| `results/data/psro/` | PSRO/PPO results by scenario, budget, condition, seed |
| `results/figures/` | Generated plots |
| `results/cache/pytest/` | Pytest cache |
| `results/wandb/` | Optional experiment tracking files |
| `results/data/verification/` | Stored baseline comparisons |

## Verification commands

```bash
python -m pytest tests/test_game_and_svi.py tests/test_results_safety.py -q
python -m pytest tests/test_six_node_ppo_regression.py -q -m slow
```

The slower suite runs **actual PPO** for 1,000 steps per response and compares
iteration 1 with historical numerical results from the same six-node scenario.
Small floating-point differences may occur across PyTorch, NumPy, SciPy,
operating system, and CPU versions. Cross-provider **bitwise** reproducibility
is not guaranteed. For meaningful scientific comparison, log package versions
and seeds along with the game/scenario configuration.

**Docker + W&B:** build with `docker build --build-arg WITH_WANDB=1 -t agt-psro:cpu-wandb .`. W&B remains optional; native Bash/Python is the recommended workflow.
